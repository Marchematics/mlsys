## Method/protocol truth audit (third pass)

A five-way audit was run over the manuscript, the algorithm, Fig. 1, the
supplement, and the implementation. Every discrepancy found is fixed.

| Item | Code truth | Was written as | Now written as |
|---|---|---|---|
| Response-scorer training states | `build_full_state_data` labels **all** $K$ candidates of a sampled state and the pairwise term runs over all candidate pairs | "Both terms are computed on shortlisted candidates, so training matches inference" | trained on states from the full training distribution, every candidate labelled; the response scorer is evaluated on the shortlist only at inference |
| Training state distribution | random subsets, size uniform in $0..B-1$, four states per episode, 16{,}000 states per run | "states sampled from the training episodes" | stated explicitly, with the train--deployment state-distribution difference named as the design's main approximation |
| Predictor granularity | `fit_subset_expert` is called inside the per-target loop in both the learned and the oracle runners | "fitted once per dataset" (main text and supplement) | fitted per target sensor on that target's windows and candidate pool, refitted for every target |
| Loss | `smooth_l1_loss` + $\beta\sum w_{ij}\,\mathrm{softplus}(-(\hat m_i-\hat m_j))$, $w_{ij}=|\tilde m_i-\tilde m_j|$ | "gap weight gives larger influence to pairs whose order can change the selection" | gap weight assigns greater importance to ranking errors with larger utility consequences and little weight to nearly tied candidates |
| Baselines' training | `sample_pair_dataset`: empty-set states for Standalone Utility, random nonempty states with one sampled candidate for cached-only | not described | described in supplement S2.5 |
| Stopping rule | stop when the best **shortlisted** score is $\le 0$ | "no remaining candidate has a positive estimated utility" | shortlist-conditional, with the screen-only certificate given as an option |
| Fig. 1 loop label | no guarantee is proved for the deployed rule | "while certified" | "update $A\leftarrow A\cup\{j^\star\}$ and repeat" |
| Statistics | two-level resampling implemented in the table builder | target-level bootstrap only | hierarchical target-then-run bootstrap, 5000 replicates, used in Table 2 |
| Supplement | three generations of experiments mixed | Electricity, old single-target METR-LA, cached-MUR narrative, "diagnostic" response model | restructured to S1--S7 around the final method; legacy protocols and tables removed; title matches the main manuscript |
| Data availability | no public repository exists yet | "a public repository link will be registered at submission" | data statement limited to what exists; a link is to be added only if it becomes public |

After the audit: main text 28 pages, review copy 39 pages, supplement 11 pages,
all with zero LaTeX warnings.

## Correction of the fixed-set baseline run (2026-09-22)

A reviewer audit of `R205_fixed_set_baselines_s3_20260921` found three defects.
All three were confirmed in the code and corrected in
`scripts/run_fixed_set_baselines_v2.py`, whose results are written to the new
and immutable run set `results/raw/R206_fixed_set_baselines_v2_s3_20260922`.
`R205` is kept on disk but is superseded and is not used by any table or figure.

| Defect | Effect | Correction |
|---|---|---|
| Negative-transfer rate compared each episode's loss against the *mean* baseline loss instead of that episode's own baseline | The reported rates were far too low (.14--.22 for greedy validation selection) and were not comparable with the other policy families, which use the per-episode definition of `src/mur/metrics.py` | The rate is now `mean(loss > base_episode)`, giving .32--.48 for the same policy |
| Cluster-based selection computed its cluster structure from the *test* batch | Test-set statistics entered the selection | The structure is estimated on the validation split and the resulting set is applied to the test episodes |
| Gradient influence ranked `2<d, r> + ||d||^2`, which is the loss *increase*, in descending order | The policy systematically selected the most harmful candidates: mean gain was -.0423 | The ranking is ascending on that quantity, i.e. descending on the estimated loss reduction; mean gain is +.0198 |

Corrected means over the six datasets (gain, harm rate):

| Policy | Gain | Harm rate |
|---|---|---|
| Greedy validation set | +.0246 | .3850 |
| Two-step lookahead set | +.0246 | .3884 |
| Gradient influence | +.0198 | .4157 |
| Adaptive-$k$ relevance | -.0010 | .5559 |
| Cluster-based selection | -.0022 | .5286 |

R-MUR remains best on every dataset and now also has the lowest harm rate
(.3346), so the manuscript sentence that had been changed to say otherwise was
restored to the correct claim. The elimination criterion still selects the same
set as plain forward selection on all 576 runs, and non-greedy lookahead still
matches greedy selection to within .0002.
